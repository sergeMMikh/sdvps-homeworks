### Задание 1

**Выполните действия, приложите файлы с плейбуками и вывод выполнения.**

Напишите три плейбука. При написании рекомендуем использовать текстовый редактор с подсветкой синтаксиса *YAML*.

Плейбуки должны: 

1. Скачать какой-либо архив, создать папку для распаковки и распаковать скачанный архив. Например, можете использовать [официальный сайт](https://kafka.apache.org/downloads) и зеркало Apache Kafka. При этом можно скачать как исходный код, так и бинарные файлы, упакованные в архив- в нашем задании не принципиально.

*Исходя из [примера установки Kafka на Linux](https://learn.arm.com/learning-paths/servers-and-cloud-computing/kafka-azure/deploy/?utm_source=chatgpt.com), где Kafka загружается и распаковывается в директорию `/opt` перед запуском, распаковка архива в `/opt/kafka` может использоваться как способ установки Kafka для быстрого старта и тестирования.*

2. Установить пакет *tuned* из стандартного репозитория вашей ОС. Запустить его, как демон — конфигурационный файл *systemd* будет создан автоматически при установке. Добавить *tuned* в автозагрузку.

*[Пакет tuned](https://redos.red-soft.ru/base/redos-7_3/7_3-administation/7_3-system-perf/7_3-tuned/) — это системная служба для динамической оптимизации производительности Linux-системы на основе текущей нагрузки и профиля использования. Он включает набор преднастроенных профилей, которые автоматически регулируют параметры ядра, планировщика ввода-вывода, частоты CPU и других подсистем для достижения оптимального поведения под заданные рабочие условия.*

3. Изменить приветствие системы (*motd*) при входе в систему. Пожалуйста, в этом задании используйте переменную для задания приветствия. Переменную можно задавать любым удобным способом.

#### Требования к результату

1. **Работа с архивом**. В качестве демонстрации результата работы скрипта покажите результат его запуска и структуру целевой директории (вывод запроса `ls` или `tree`).

2. **Пакет *tuned***. Здесь, помимо результата запуска *playbook* следует показать скриншоты вывода запроса версии установленного пакета и статуса соответсвующего сервиса.

3. **Приветствие системы при входе**. Помимо результата запуска скрипта следует привести скриншот самого приветсвия при входе в систему.

4. Ко всем трём пунктам требуется приложить ссылки на `.yaml` (`.yml`) файлы *playbook*. Просто текст кода в решении, как и его скриншоты, не принимается.

### Задание 3

**Выполните действия, приложите архив с ролью и вывод выполнения.**

Ознакомьтесь со статьёй [«Ansible - это вам не bash»](https://habr.com/ru/post/494738/), сделайте соответствующие выводы и не используйте модули **shell** или **command** при выполнении задания.

Создайте плейбук, который будет включать в себя одну, созданную вами роль. Роль должна:

1. Установить веб-сервер Apache на управляемые хосты.
2. Сконфигурировать файл `index.html` c выводом характеристик каждого компьютера как веб-страницу по умолчанию для Apache. Необходимо включить *CPU*, *RAM*, величину первого *HDD*, *IP*-адрес.
Используйте [`Ansible facts`](https://docs.ansible.com/ansible/latest/playbook_guide/playbooks_vars_facts.html) и [`jinja2-template`](https://linuxways.net/centos/how-to-use-the-jinja2-template-in-ansible/). Необходимо реализовать *handler*: перезапуск *Apache* только в случае изменения файла конфигурации *Apache*.
4. Открыть порт 80, если необходимо, запустить сервер и добавить его в автозагрузку.
5. Сделать проверку доступности веб-сайта (ответ 200, модуль uri).

#### Требования к результату

1. Предоставьте ссылку на `.yaml` (`.yml`) файл *playbook*, использующий роль;
2. Разместите архив созданной роли у себя на *Google диске* и приложите ссылку на роль в своём решении. Архив с ролью рассматривается как самостоятельный программный продукт, а потому:
 - должен иметь соответствующую структуру;
 - не должен содержать лишних файлов типа *inventory* или *ansible.cfg*.
3. Предоставьте скриншоты выполнения плейбука;
4. Предоставьте скриншот браузера, отображающего сконфигурированный *index.html* в качестве сайта.
